## 1. Что такое Gamestore простыми словами

**Gamestore** — это интернет-магазин видеоигр. Обычный магазин, только в браузере.

Представь витрину игрового магазина, но в интернете:
- на **главной странице** — лучшие игры и подборки по жанрам (Action, RPG, Sports);
- в **каталоге** — все игры с фильтрами (категория, платформа, рейтинг PEGI, цена, наличие);
- у каждой игры **своя страница**: обложка, описание, разработчик, выбор платформы и издания;
- понравившуюся игру кладёшь в **корзину**;
- из корзины оформляешь **заказ**: вводишь имя, телефон, адрес, выбираешь способ оплаты;
- заказ попадает в **админ-панель**, где сотрудник видит его и обрабатывает;
- посетители могут отправить **заявку через форму «Контакты»** — она тоже сохраняется в базе и видна в админке.

Покупателю **не нужно регистрироваться** — заказ оформляется анонимно, как в обычном магазине:
пришёл, выбрал, оформил.

Магазин состоит из двух частей:
- **Витрина (для покупателя)** — то, что видит клиент: каталог, карточки игр, корзина, оформление.
- **Админ-панель (для сотрудника)** — управление играми, вариантами, заказами, заявками с контактов.

## 2. Словарь: что значат все страшные слова

Прочитай этот раздел один раз — и весь остальной документ станет понятным.

| Слово | Объяснение «на пальцах» |
|-------|------------------------|
| **Сайт / веб-приложение** | Программа, которая открывается в браузере (Chrome, Firefox). |
| **Браузер** | Программа, через которую ты заходишь в интернет. |
| **Сервер** | Мощный компьютер, на котором «живёт» сайт. Он всё время включён и отвечает на запросы. |
| **Клиент** | Твой браузер. Он *просит* у сервера страницы. Сервер — *отдаёт*. |
| **Запрос (request)** | Когда браузер говорит серверу: «дай мне страницу каталога». |
| **Ответ (response)** | То, что сервер присылает обратно: готовую HTML-страницу. |
| **HTTP** | «Язык», на котором браузер и сервер разговаривают. GET = «дай», POST = «на, сохрани». |
| **Бэкенд (backend)** | «Мозг» сайта на сервере. Здесь вся логика: проверки, работа с базой. У нас — Python/Django. |
| **Фронтенд (frontend)** | То, что видит пользователь: кнопки, цвета, текст. У нас — HTML, CSS, немного JavaScript. |
| **HTML** | Язык разметки. Описывает *что* на странице: заголовок, кнопка, картинка. |
| **CSS** | Язык стилей. Описывает *как выглядит*: цвет, размер, расположение. |
| **JavaScript (JS)** | Язык, который работает прямо в браузере и оживляет страницу (форма оплаты картой). |
| **База данных (БД)** | Большая умная таблица (как Excel), где хранятся все данные: игры, заказы, варианты. |
| **SQL** | Язык, которым задают вопросы базе данных: «дай все игры дешевле 15000». |
| **ORM** | Переводчик между Python и базой. Пишешь Python — ORM сам превращает это в SQL. |
| **Модель (Model)** | Описание одной таблицы в базе на языке Python. Например, модель `Product` = таблица игр. |
| **Миграция** | «Инструкция по сборке таблиц». Django читает модели и создаёт таблицы в базе. |
| **View (вью, представление)** | Функция на бэкенде, которая обрабатывает запрос и решает, что показать. |
| **Template (шаблон)** | Заготовка HTML-страницы с «дырками», куда вставляются данные из базы. |
| **URL / маршрут** | Адрес страницы. Например `/catalog/` — список игр. URL связывает адрес и нужную view. |
| **Сессия (session)** | «Память сайта о тебе». У нас в сессии хранится корзина — что ты выбрал. |
| **Cookie (куки)** | Маленькая записка, которую сервер кладёт в браузер, чтобы узнавать тебя между страницами. |
| **CSRF-токен** | Секретная защита форм, чтобы злоумышленник не отправил форму от твоего имени. |
| **Вариант (variant)** | Конкретное сочетание платформа + издание одной игры, со своим остатком на складе. |
| **Платформа** | Консоль или компьютер, на которой запускается игра: PS5, Xbox Series X, Nintendo Switch, PC. |
| **Издание** | Версия игры: Standard, Deluxe, Ultimate, Gold — отличаются набором бонусов. |
| **SKU / артикул** | Уникальный код варианта, например `GTA-VI-PS5-STANDARD`. |
| **PEGI** | Европейская система возрастных рейтингов игр: PEGI 3, 7, 12, 16, 18. |
| **Скидка (discount)** | Процент, на который снижается цена. Итоговая цена считается автоматически. |
| **Деплой** | Выложить сайт в интернет, чтобы он был доступен всем, а не только на твоём ноутбуке. |

## 3. Как вообще работает любой сайт

Когда ты открываешь страницу магазина, происходит такая цепочка:

```
ТЫ вводишь адрес /catalog/
        │
        ▼
1. БРАУЗЕР отправляет ЗАПРОС на сервер: «дай мне страницу /catalog/»
        │
        ▼
2. СЕРВЕР (Django) смотрит в файл urls.py: «какой адрес? /catalog/?
   Значит надо вызвать функцию catalog»
        │
        ▼
3. ФУНКЦИЯ (view) идёт в БАЗУ ДАННЫХ и берёт оттуда все активные игры
        │
        ▼
4. ФУНКЦИЯ вставляет игры в ШАБЛОН (HTML-заготовку catalog.html)
        │
        ▼
5. СЕРВЕР отправляет готовую HTML-страницу обратно
        │
        ▼
6. БРАУЗЕР показывает тебе каталог игр
```

Этот шаблон проектирования называется **MVT** (Model — View — Template):

- **Model** (модель) — отвечает за данные и базу. Файл `models.py`.
- **View** (представление) — отвечает за логику «что делать с запросом». Файл `views.py`.
- **Template** (шаблон) — отвечает за внешний вид. Папка `templates/`.

> 💡 **Главная мысль для защиты:** в Django каждый запрос проходит путь
> `URL → View → Model (база) → Template → ответ`. Запомни эту цепочку — это 80% понимания проекта.

## 4. Технологии проекта и зачем каждая

| Технология | Что это | Зачем в проекте |
|------------|---------|-----------------|
| **Python 3.12+** | Язык программирования | Основной язык, на нём написан весь бэкенд («мозг») |
| **Django 6.0** | Веб-фреймворк (готовый каркас сайта) | Принимает запросы, работает с базой, собирает страницы. Экономит месяцы работы |
| **SQLite 3** | Простая база данных в одном файле | Хранит все данные. Файл `db.sqlite3`. Не требует установки отдельного сервера БД |
| **Django ORM** | Переводчик Python ↔ SQL | Позволяет работать с базой на Python, без ручного SQL |
| **Django Templates** | Шаблонизатор HTML | Собирает HTML-страницы на сервере, вставляя данные в заготовки |
| **HTML + CSS** | Языки фронтенда | Внешний вид страниц. Свой `styles.css` без Bootstrap — написан с нуля |
| **JavaScript** | Язык браузера | Лёгкий интерактив: показ полей карты при оплате картой, маски ввода |
| **Google Fonts** | Веб-шрифты | Шрифты Rajdhani (заголовки) и Inter (текст) для игрового дизайна |
| **Паттерн MVT** | Архитектура Django (Model–View–Template) | Разделяет данные, логику и внешний вид — код понятный и расширяемый |

> В проекте сознательно **не использованы** React, Vue, Bootstrap, сторонние API —
> всё на «чистом» Django, чтобы код был прозрачным и его легко было объяснить на защите.

## 5. Как запустить проект на своём компьютере

### Что нужно заранее
- Установленный **Python 3.12+** (при установке поставить галочку *Add Python to PATH*).
- Терминал (PowerShell на Windows или Terminal на Mac/Linux).

### Шаг 1 — Открыть папку проекта
Открой терминал в папке проекта `Dernavoy-magaz`.

### Шаг 2 — Создать виртуальное окружение
```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Mac / Linux:
source .venv/bin/activate
```
*Объяснение:* **виртуальное окружение** — отдельная коробка с библиотеками только для этого
проекта. Чтобы библиотеки разных проектов не мешали друг другу.

### Шаг 3 — Установить библиотеки
```bash
pip install -r requirements.txt
```
*Объяснение:* читает файл `requirements.txt` (список библиотек) и скачивает их все.

### Шаг 4 — Создать таблицы в базе данных
```bash
python manage.py migrate
```
*Объяснение:* команда `migrate` читает все модели и создаёт таблицы в базе.
Это обязательный шаг — без него сайт не запустится.

### Шаг 5 — Заполнить базу демо-данными
```bash
python manage.py seed_shop --reset
```
*Объяснение:* наша собственная команда. Создаёт **8 категорий и 8 игр** с вариантами
платформ и изданий, чтобы сайт не был пустым.
`--reset` сначала очищает каталог, потом заполняет заново.

### Шаг 6 — Создать администратора
```bash
python manage.py createsuperuser
```
*Объяснение:* создаёт аккаунт для входа в панель управления `/admin/`.
Запросит логин, email и пароль.

### Шаг 7 — Запустить сервер
```bash
python manage.py runserver
```
Открой в браузере **http://127.0.0.1:8000/** — это витрина магазина.

> `127.0.0.1` (или `localhost`) — «этот же компьютер». `8000` — номер «двери» (порта).

## 5.1. 🌐 Запуск в локальной сети (открыть с телефона)

По умолчанию сайт виден только на самом компьютере. Чтобы открыть его
**с телефона** в той же Wi-Fi сети — выполни 4 шага.

### Шаг 1 — Узнать IP-адрес компьютера
- **Windows:** `ipconfig` → строка **IPv4-адрес**, например `192.168.0.105`.
- **Linux:** `hostname -I` → первый адрес.

### Шаг 2 — Добавить IP в настройки
Открой `config/settings.py` и добавь свой IP в `ALLOWED_HOSTS`:
```python
ALLOWED_HOSTS = ["127.0.0.1", "localhost", "testserver", "192.168.0.105"]
```

### Шаг 3 — Запустить сервер «на всю сеть»
```bash
python manage.py runserver 0.0.0.0:8000
```

### Шаг 4 — Открыть с телефона
```
http://192.168.0.105:8000/
```

## 8. База данных: таблицы, поля, связи

|------|-----|-----------|

| `description` | текст | Описание категории |

### Таблица `Product` — игры (главная таблица)
| Поле | Тип | Что хранит |
|------|-----|-----------|
| `category` | связь → Category | К какой категории относится |
| `name` | строка | Название игры («GTA VI», «Elden Ring») |
| `slug` | строка | Адресная часть для URL |
| `description` | текст | Описание игры |
| `developer` | строка | Разработчик / издатель («Rockstar Games») |

| `discount_percent` | число | Процент скидки (0–100) |
| `is_featured` | да/нет | Показывать ли на главной странице |
| `is_active` | да/нет | Виден ли товар в каталоге |
| `created_at / updated_at` | дата | Когда создан / изменён |

### Таблица `ProductImage` — изображения игры
| Поле | Тип | Что хранит |
|------|-----|-----------|
| `product` | связь → Product | Чьё изображение |
| `image_url` | ссылка | Адрес обложки |
| `alt_text` | строка | Подпись для SEO |
| `is_primary` | да/нет | Главное ли изображение |

### Таблица `ProductVariant` — варианты (платформа + издание)
| Поле | Тип | Что хранит |
|------|-----|-----------|
| `product` | связь → Product | Чей вариант |
| `sku` | строка | Артикул (уникальный код варианта) |
| `platform` | выбор | Платформа: ps5 / xsx / ps4 / xone / switch / pc |
| `edition` | выбор | Издание: standard / deluxe / ultimate / gold |
| `stock` | число | Остаток на складе |

У одной игры уникальна пара «платформа + издание».

### Таблица `Order` — заказы
| Поле | Тип | Что хранит |
|------|-----|-----------|
| `full_name` | строка | Имя клиента |
| `phone` | строка | Телефон |
| `email` | почта | Email (необязательно) |
| `city / address` | строка | Город и адрес доставки |
| `comment` | текст | Комментарий к заказу |
| `total_amount` | деньги | Итоговая сумма заказа |
| `status` | выбор | Новый / В обработке / Завершён / Отменён |

| `order` | связь → Order | К какому заказу |
| `product / variant` | связь | Какая игра и вариант |
| `item_title` | строка | Название игры на момент заказа |
| `quantity` | число | Количество |
| `unit_price` | деньги | Цена за штуку на момент заказа |

### Таблица `ContactRequest` — заявки с контактов
| Поле | Тип | Что хранит |
|------|-----|-----------|
| `name` | строка | Имя отправителя |
| `email` | почта | Email |
| `phone` | строка | Телефон (необязательно) |
| `topic` | строка | Тема обращения |
| `message` | текст | Текст сообщения |
| `status` | выбор | Новая / В работе / Обработана |
| `created_at` | дата | Когда отправлена |

### Схема связей (кто на кого ссылается)
```
Category       1 ──< many  Product
Product        1 ──< many  ProductImage
Product        1 ──< many  ProductVariant
Order          1 ──< many  OrderItem
OrderItem      >──          Product, ProductVariant
ContactRequest              (независимая таблица, хранит заявки с формы контактов)
```

Читается так: «1:many» = «один ко многим». У одной игры может быть много вариантов
(PS5 Standard, PS5 Deluxe, PC Standard и т.д.).

## 11. Как работает каждая функция по шагам

### 11.1. Каталог: поиск, фильтры, сортировка

1. View `catalog` берёт параметры из адреса (`?q=...&platform=ps5&age_rating=pegi18`).
2. Через ORM строит запрос:
   - поиск по названию или разработчику (оператор «ИЛИ»);
   - фильтр по категории (`category__slug=selected_category`);
   - фильтр по платформе (`variants__platform=selected_platform`);
   - фильтр по возрастному рейтингу (`age_rating=selected_age_rating`);
   - диапазон цен (`price__gte`, `price__lte`);
   - наличие (`variants__stock__gt=0`).
3. `.distinct()` — убирает дубли (игра не появляется дважды если есть 2 варианта на PS5).
4. Применяет сортировку и разбивает на страницы по 12 игр.

### 11.2. Карточка игры и варианты

Собираются доступные платформы и издания из вариантов.
Вариант без остатка показывается в списке как недоступный (атрибут `disabled`).
Похожие игры — из той же категории, не более 4.

### 11.3. Корзина (на основе сессии)

1. С карточки игры отправляется POST на `/product/<slug>/add/` (игра + вариант + количество).
2. `cart.py` проверяет остаток и кладёт позицию в сессию.
   Ключ позиции — строка `"id_игры:id_варианта"`.
3. Итог пересчитывается с учётом скидок при каждом открытии корзины.

### 11.4. Оформление заказа и списание остатков (главная логика)

1. Покупатель заполняет `CheckoutForm`; данные карты (если выбрана) проверяются форматом.
2. Перед сохранением система проверяет, что каждого варианта **хватает на складе**.
3. В **одной транзакции** создаются `Order` и `OrderItem`, **остатки списываются**,
   считается итоговая сумма.
4. Полные данные карты **не сохраняются** — только последние 4 цифры.
5. Корзина очищается, открывается страница подтверждения.

Что такое транзакция — если в процессе заказа произойдёт ошибка, **ничего не сохранится**.
Нет «половинчатых» заказов: либо заказ создан целиком, либо нет вообще.

### 11.5. Скидки

Если у игры есть `discount_percent`, итоговая цена = цена − процент скидки
(свойство `final_price`), округляется до тиын.
Пример: цена 19990 ₸, скидка 10% → итог 17991 ₸.

### 11.6. Сохранение заявок с контактов

1. Посетитель заполняет форму на `/contacts/` (имя, email, телефон, тема, сообщение).
2. View `contacts` вызывает `ContactForm` и проверяет данные.
3. Если данные корректны — создаётся запись `ContactRequest` в базе со статусом «Новая».
4. Пользователь видит сообщение «Спасибо! Мы скоро свяжемся с вами».
5. Менеджер видит заявку в разделе **«Заявки с контактов»** в админке, может сменить статус
   на «В работе» или «Обработана» прямо из списка.

### 11.7. Адаптивный (мобильный) дизайн

Через CSS-медиазапросы (`@media`) страницы корректно отображаются на телефоне и планшете:
- Сетка продуктов — 2 колонки на телефоне вместо 4.
- Панель фильтров — перестраивается в 2 колонки.
- Двухколоночные блоки (корзина, детали товара) — становятся одноколоночными.

## 13. Безопасность проекта

Это любимая тема комиссии.

1. **CSRF-токены во всех формах** — защита от подделки запросов. В каждой форме Django
   автоматически добавляет скрытое поле `{% csrf_token %}`. Без него форму не примут.
   Это мешает злоумышленнику отправить форму от имени пользователя с другого сайта.

2. **Платёжные данные не хранятся** — в базе сохраняются только **последние 4 цифры** карты
   для идентификации. Полный номер, CVV и срок действия нигде не сохраняются.

3. **Транзакции при оформлении заказа** — заказ либо создаётся целиком со списанием
   остатков, либо не создаётся вовсе. Нет ситуации «деньги списаны, а заказа нет».

4. **Проверка остатков перед заказом** — нельзя купить то, чего нет на складе.
   Если между добавлением в корзину и оформлением кто-то купил последний экземпляр,
   пользователь получит сообщение об ошибке.

5. **Экранирование данных в шаблонах** — Django автоматически превращает символы `<`, `>`
   в безопасные `&lt;`, `&gt;`. Это защищает от **XSS** — нельзя вставить вредоносный скрипт
   через поле имени или комментария.

6. **Доступ к админ-панели** — только после входа администратора. Обычный посетитель
   не может открыть `/admin/`.

7. **Валидация формы карты** — проверяется формат номера карты (13–19 цифр), CVV (3–4 цифры),
   срок действия (формат MM/YY). Некорректные данные возвращают ошибку.

## 14. Возможные вопросы комиссии и готовые ответы

**В: На чём написан проект?**
О: Бэкенд — Python и фреймворк Django 6. База данных — SQLite. Фронтенд — HTML, CSS и
немного JavaScript. Архитектура — паттерн MVT (Model–View–Template).

**В: Почему выбрана база SQLite, а не PostgreSQL?**
О: SQLite — это база в одном файле, не требует отдельного сервера, идеальна для разработки
и демонстрации. При необходимости проект легко переводится на PostgreSQL — нужно только
изменить одну строку в `settings.py`.

**В: Что такое MVT?**
О: Model — View — Template. Model отвечает за данные (модели в `models.py`). View — за логику
(функции в `views.py`). Template — за внешний вид (HTML в `templates/`). Это архитектурный
паттерн фреймворка Django.

**В: Почему нет регистрации пользователей?**
О: Магазин рассчитан на анонимные покупки, как офлайн-магазин: клиент выбирает товар и
оформляет заказ без аккаунта. Корзина хранится в сессии браузера.

**В: Где хранится корзина?**
О: В сессии браузера, не в базе данных. Структура — словарь `{ "id_игры:id_варианта": количество }`.
При оформлении заказа она превращается в записи `Order` и `OrderItem` в базе.

**В: Как считается цена со скидкой?**
О: Свойство `final_price` модели `Product`: цена минус процент скидки, округление до тиын.
Например: 19990 ₸ со скидкой 10% → 17991 ₸.

**В: Что происходит при оформлении заказа?**
О: Проверяется наличие каждого варианта на складе. Затем в **одной транзакции** создаётся
заказ с позициями и списываются остатки. Полные данные карты не сохраняются — только 4 последние цифры.

**В: Что такое вариант товара?**
О: Конкретное сочетание платформы и издания со своим артикулом и остатком на складе.
Например: «GTA VI — PlayStation 5 — Deluxe Edition». Одна игра может иметь много вариантов.

**В: Как реализовано управление заявками с контактов?**
О: При отправке формы на странице «Контакты» создаётся запись в таблице `ContactRequest`.
В админ-панели появляется раздел «Заявки с контактов», где менеджер видит все обращения
и может менять им статус: Новая → В работе → Обработана.

**В: Как защищён проект?**
О: CSRF-токены в формах, отказ от хранения полных данных карты, транзакции и проверка
остатков при заказе, экранирование пользовательского ввода (защита от XSS), вход в
админку по паролю, валидация всех форм на бэкенде.

**В: Что делает команда `seed_shop`?**
О: Это собственная management-команда Django. Наполняет базу демо-данными: 8 категорий игр
(Action, RPG, Strategy, Sports, Horror, PS5, Nintendo, PC Games) и 8 игр с вариантами
платформ и изданий — чтобы сайт можно было сразу показать.

**В: Как добавить новое поле в игру?**
О: Добавить поле в `shop/models.py`, выполнить `python manage.py makemigrations` (создаст
инструкцию изменения базы) и `python manage.py migrate` (применит её).

**В: Что такое миграция?**
О: Инструкция по изменению структуры базы данных. Когда мы добавляем новое поле в модель,
Django создаёт файл-миграцию с описанием изменений, а команда `migrate` применяет их к базе.
